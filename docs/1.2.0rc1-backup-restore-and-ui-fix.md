# DSHA 1.2.0rc1 备份恢复完整性修复与黑色按钮消除记录

## 一、背景与问题概述

在 DSHA（Android 容器运行环境）1.2.0rc1 测试版本中，用户反馈并经排查发现了以下两类核心问题：

1. **界面 UI 异常（黑色按钮）**：
   - 启动页的“插件导致启动失败？安全启动”按钮背景呈现为纯黑色胶囊状，文字暗灰无法辨识；
   - 诊断与修复页的“返回”、“重新诊断”、“修复证书与 npm”、“前往插件页使用备用文件选择器”、“复制反馈信息”、“导出诊断报告”全部呈现为纯黑背景。
2. **数据与备份严重缺陷**：
   - **对话丢失**：使用“仅备份对话记录”功能恢复后，WebUI 侧边栏的对话列表完全为空；
   - **工作区代码 0 备份**：全量备份弹窗承诺“备份工作区文件”，但实际上只打包了 `/root/.dsh`，用户在手机公开存储 `/sdcard/Download/DSHA/工作区` 中的工程代码与文档完全未被打包；换机恢复后工作区代码全部丢失；
   - **Android 11+ MediaStore 重命名冲突**：多次备份或同名覆盖导出时，系统将文件重命名为 `(1).tar.gz` 导致后续校验失败；
   - **恢复时服务未停机**：恢复覆盖底层文件时 DSH 服务仍在运行，可能导致文件句柄损坏且恢复后无重启提示；
   - **设置页工作区路径控件未绑定**：`workspace_path` 与 `workspace_apply` 控件在代码中为摆设，点击无响应。

---

## 二、问题根本原因分析

### 1. 黑色按钮（黑底黑字）成因
在 `res/values/themes.xml` 中，为了避免 Material3 把 `<Button>` 膨胀为 `MaterialButton` 时自带的 primary 着色覆盖自定义背景，全局将 `materialButtonStyle` 指向了自定义的 `Widget.DSHA.Button`。
然而在 `res/values/styles.xml` 中：
```xml
<style name="Widget.DSHA.Button" parent="Widget.Material3.Button.TextButton">
    <item name="backgroundTint">@null</item>
    <item name="android:textAllCaps">false</item>
    <item name="android:textColor">@color/text</item>
    ...
</style>
```
该样式将 `backgroundTint` 设为了 `@null`，但**漏写了默认的 `android:background`**。
在 Android 布局中，显式声明了 `android:background="@drawable/bg_btn"` 的按钮正常显示；但未显式写 `android:background` 的按钮（如安全启动按钮、诊断页各按钮）回退到 MaterialButton 内部 ShapeDrawable 时，由于缺少 Tint 着色，绘制引擎默认使用黑色（#000000）绘制底色，搭配浅色模式下的深灰色文字 `@color/text`（#1A2230），形成严重的黑底黑字。

### 2. 仅恢复对话后 WebUI 侧边栏为空成因
DSH 1.2+ 的会话索引依赖 `.dsh/storages/workspace.json`（记录工作区与各 session ID 的映射注册表）。
备份端在 `BackupScope.SESSIONS` 正确打包了 `.dsh/sessions` 和 `.dsh/storages`；
但恢复脚本 `restore-merge.py` 第 863 行硬编码为：
```python
ok_dsh = restore_dsh_subtree(stage, root, ["sessions"], alpha=alpha)
```
漏恢复了 `storages`！导致底层 `.jsonl` 对话文件被复制到了磁盘，但因索引表未恢复，WebUI 侧边栏无法加载历史对话。

### 3. 工作区文件 0 备份与换机路径失效成因
- **备份端缺失**：工作区路径并不固定（由用户在 WebUI 中自由选择，如 `/sdcard/Download/DSHA/工作区`），保存于 `workspace.json` 中。原打包脚本 `buildTarScript` 仅写死打包 `.dsh`，根本没有扫描 `workspace.json` 收集工作区文件。
- **换机路径冲突**：若直接备份绝对路径，换机恢复后若目标机存储路径变动或私有路径失效，DSH 启动时执行 cwd 目录检查失败，会自动把会话从注册表中除名（剪枝），导致不仅代码丢失，对话也会随之消失。

## 三、系统性修复方案与代码实现

### 1. 彻底根除 UI 按钮变黑
- 在 `app/src/main/res/values/styles.xml` 中，为 `Widget.DSHA.Button` 增加全局默认背景：
  ```xml
  <item name="android:background">@drawable/bg_btn</item>
  ```
- 同步规范化 `fragment_launch.xml`、`activity_diagnostics.xml`、`activity_update.xml`、`activity_plugin_install.xml` 中的所有按钮属性（显式指定 background、textColor、边距及大小写规范）。

### 2. 恢复会话索引，彻底解决对话不显示
在 `app/src/main/assets/restore-merge.py` 中：
```python
if scope == "sessions":
    say("· 这是「只对话」备份：只覆盖对话记录与会话索引，配置与插件保持现状")
    ok_dsh = restore_dsh_subtree(stage, root, ["sessions", "storages"], alpha=alpha)
    ok_dsh = restore_pub_snapshot(stage, root, only=["sessions", "storages"]) or ok_dsh
```
确保 `workspace.json` 索引随会话同步还原。

### 3. 动态工作区相对归档与换机智能重映射
- **备份端（`BackupManager.java`）**：
  在全量备份打包前，自动执行 Python 脚本读取 `workspace.json`，将各个注册的工作区代码文件归档至 `.dsha-workspaces/<wid>/`，自动排除 `node_modules`、`.git`、`dist` 等重型缓存目录，并生成包含原始路径信息的 `meta.json` 随包打入。
- **恢复端（`restore-merge.py`）**：
  新增 `restore_workspaces(stage, root)` 函数：
  1. 原路径可写时直接还原到原工作区路径；
  2. 跨机或原路径不可写时，自动重映射至新机器公开存储（`/sdcard/Download/DSHA/<title>`）；
  3. 自动同步更新 `workspace.json` 中的工作区路径为新路径，配合 `ensure_workspace_dirs` 杜绝会话剪枝。

### 4. 运行态避让与交互增强
- **恢复前停止服务**：`WorkspaceFragment.doRestore()` 在后台恢复执行前先调用 `controller.stopWeb()`，释放文件句柄；
- **恢复后提供重启**：弹窗提供“立即重启服务”选项，便于用户一键加载恢复后的数据；
- **工作区路径绑定**：在 `WorkspaceFragment.java` 中绑定 `workspace_path` 与 `workspace_apply`，使配置修改即时生效；
- **文件选择兼容性**：`OpenDocument` 传入 `*/*`，防止部分机型 MIME 解析异常将 `.tar.gz` 置灰；
- **解决 MediaStore 冲突**：`BackupManager.exportArchive()` 优先使用直接文件覆盖写入（利用 `MANAGE_EXTERNAL_STORAGE`），避免系统重命名为 `(1).tar.gz`。
