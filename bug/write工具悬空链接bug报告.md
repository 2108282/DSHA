# Write 工具「悬空符号链接」Bug 报告

> 现象：通过 Write 工具创建文件后，路径显示为符号链接且指向不存在的目标，文件实际不可读。
> 本报告为纯技术记录，不含任何个人信息。

---

## 一、Bug 概要

| 项目 | 内容 |
|---|---|
| 影响工具 | 文件写入工具（Write） |
| 现象 | 工具返回「Created file」，但生成的是悬空符号链接，目标文件不存在 |
| 复现率 | 3 / 3（100% 确定性复现，非偶发） |
| 触发环境 | 容器文件系统 L2 存储层（路径为 /root 下） |
| 数据影响 | 内容丢失或滞留于暂存目录；工具报告成功但文件不可读 |

## 二、复现步骤与结果

### 步骤

1. 用 Write 工具创建文件（如 /root/reports/xxx.md）
2. 用 `ls -la` 查看 → 文件是符号链接
3. 用 `readlink` 查看链接目标
4. 用 `cat`/`wc` 读取 → 报 No such file or directory

### 三次复现记录

| # | 文件名 | 链接指向 | 实际落盘 | 结果 |
|---|---|---|---|---|
| 1 | adb-直连问题排查报告.md（中文） | .tmpdir/.l2s.xxx.tmp0001 | .tmpdir/.l2s.xxx.tmp0001.0001（带 .0001 后缀） | 悬空 |
| 2 | adb-direct-connect-report.md（英文） | .tmpdir/.l2s.xxx.tmp0001 | .tmpdir/.l2s.xxx.tmp0001.0001（带 .0001 后缀） | 悬空 |
| 3 | bug-repro-test.txt（纯 ASCII） | .tmpdir/.l2s.xxx.tmp0001 | 目录与文件均不存在 | 纯悬空 |

结论：与文件名语言（中文/英文/ASCII）无关，与内容大小无关（8 字节测试文件同样中招），确定性复现。

## 三、证据

```
$ ls -la /root/reports/
lrwxrwxrwx bug-repro-test.txt -> /root/reports/.bug-repro-test.txt.27836.xxx.tmpdir/.l2s.bug-repro-test.txt.tmp0001

$ cat /root/reports/bug-repro-test.txt
cat: bug-repro-test.txt: No such file or directory
```

- 形态 A：链接指向 `.tmp0001`，实际落盘名为 `.tmp0001.0001`（多 `.0001` 后缀）→ 链接目标与落盘名不一致
- 形态 B：链接指向的整个 tmpdir 目录都不存在 → 纯悬空

## 四、根因推测

Write 工具的 L2 存储层写入流程疑似为：

```
内容写入暂存（.tmpdir/.l2s.<name>.tmpNNNN）→ 创建最终路径符号链接 → 移动/重命名落盘
```

推测故障点：

1. 暂存文件落盘时被附加序号后缀（.0001），但符号链接按无后缀名创建 → 目标名不匹配（形态 A）
2. 暂存内容后续被清理/未真正落盘，链接先行创建 → 纯悬空（形态 B）
3. 最终路径的符号链接创建成功，但真实文件移动步骤失败或顺序颠倒，且无失败回滚

## 五、影响

- 用户侧表现：「文件写入失败/不存在」，与工具返回的「Created file」矛盾
- 数据看似丢失，实际可能滞留暂存目录（可尝试从 .tmpdir 找回）
- 影响所有通过 Write 工具落盘的产物（报告、脚本、配置等）

## 六、规避方案（全部实测验证）

| # | 方案 | 状态 | 说明 |
|---|---|---|---|
| 1 | bash 直写（heredoc / echo 重定向） | ✅ 可用 | `cat > file <<'EOF' ... EOF`，真实落盘，中文/英文均正常 |
| 2 | /tmp 中转 + mv | ✅ 可用 | `echo x > /tmp/t && mv /tmp/t 目标路径`，mv 到新路径不经过 L2 暂存 |
| 3 | edit 工具（修改既有文件） | ✅ 可用 | 对已存在的文件做修改更新时真实落盘，不触发本 bug |
| 4 | write 工具（新建文件） | ❌ 不可用 | 100% 悬空，避开 |
| 5 | /sdcard 等外部路径直写 | ❌ 不可用 | 容器沙箱拒绝（Operation not permitted） |

> 关键线索：edit 工具更新路径正常、write 工具新建路径悬空 → 本 bug 只存在于 write 工具的**新建流程**（暂存 → 建链接 → 落盘），而非整个 L2 存储层。

## 七、数据恢复（已踩坑文件怎么救）

| 形态 | 判定 | 恢复方法 |
|---|---|---|
| 形态 A（tmpdir 目录仍在） | 内容滞留于 `.tmpdir/.l2s.<name>.tmp0001.0001` | 直接 cp 出来即可（已实测成功恢复一份 6202B 的报告） |
| 形态 B（tmpdir 目录不存在） | 内容真丢失 | 无法恢复，需重新生成 |

恢复命令示例：

```bash
cp "/目标目录/.xxx.tmpdir/.l2s.xxx.tmp0001.0001" /目标目录/恢复文件名
```

## 八、修复建议

1. 链接目标名与落盘文件名保持同一来源（同一变量），杜绝后缀不一致
2. 创建链接前先确认目标文件已落盘；失败则删除链接并返回错误
3. 增加写入后自检：创建完成后验证目标可读，不可读则回滚并报错
4. 提供从 .tmpdir 暂存恢复内容的兜底路径
5. 修复重点定位在 write 工具的「新建流程」：暂存文件落盘时被附加 `.0001` 序号后缀，但链接按无后缀名创建，两者应使用同一命名来源；且新建成功前不应提前返回「Created file」
