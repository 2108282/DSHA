# DSHA 后台心跳与待机功耗排查

## 一、 问题背景与排查起源

在 DSHA 运行期间，用户观察到：
1. **持续 CPU 心跳**：主进程 `com.dsh.client` 下的 `HarnessService` 后台持续活跃，即使在夜间睡觉待机状态下也无法静默；
2. **微观高频跳动**：进一步观察发现不仅存在宏观周期，甚至每一秒都有 CPU 和网络数据心跳；
3. **数据传输现象**：在手机进程管理中，DSHA 呈现微小且绝对对称的数据流动（`↑ 164 B/s  ↓ 164 B/s`）。

---

## 二、 全链路心跳源定位与底层剖析（抓包与系统调用铁证）

通过在容器与宿主底层挂载 `strace` 系统调用跟踪器、采样 `/proc/<pid>/task/*/stat` 以及抓取 Socket 连接，全量定位出 6 处心跳与唤醒源：

### 1. 微观每秒渲染空转：`QuickChatSheetActivity` 常驻单例
- **代码位置**：`app/src/main/java/com/deepseekharness/app/ui/QuickChatSheetActivity.java`
- **机制**：为了实现快捷对话抽屉“零转圈秒开”，代码常驻了全局静态 `sCachedWebView`。但该 Activity 未实现 `onPause()`，抽屉收起后仅从 View 树 `removeView`，**从未调用 `sCachedWebView.pauseTimers()` 和 `onPause()`**。
- **后果**：WebView 内部的 V8 引擎、requestAnimationFrame 渲染与 React/Vite 前端定时器在后台以 100% 算力全速空转，`RenderThread`、`VizWebView`、`Chrome_InProcGp` 每一秒都在密集产生 CPU ticks。

### 2. 每 2 秒数据传输脉冲（164 B/s）：上游 WebSocket 默认心跳
- **代码位置**：`@deepseek-ai/dsh-api-gateway/lib/index.js`
- **底层铁证**：使用 `strace` 对 `NetworkService` 线程（TID 14218）与容器 Node.js 进程抓包，捕获到底层数据：
  ```text
  [pid 14218] sendto(324, "\212\200\373\377\257]", 6, MSG_NOSIGNAL, ...) = 6  # 十六进制 8A 80，即 WebSocket PONG 帧
  [pid 13806] read(25, "\212\200\373\377\257]", 65536) = 6
  ```
- **机制**：上游将 WebSocket 心跳硬编码为 `DEFAULT_WEBSOCKET_HEARTBEAT_INTERVAL_MS = 2000`（2 秒）。每 2 秒 Node 发送一次 Ping，WebView C++ 协议栈回复 6 字节 Pong。加上 TCP/IP 协议头和 ACK 确认包，在 127.0.0.1 本地回环上网卡统计出绝对对称的：
  $$\frac{164 \text{ 字节} \times 2}{2 \text{ 秒}} = 164 \text{ B/s}$$
  每 2 秒将休眠中的 CPU 和网络协议栈强行踢醒一次。

### 3. 每 15 秒看门狗敲门：`HarnessService` TCP 探活
- **代码位置**：`app/src/main/java/com/deepseekharness/app/HarnessService.java`
- **机制**：线程 `dsha-keepalive` 每 15 秒执行一次 `isWebUp()`，发起 `Socket.connect(new InetSocketAddress("127.0.0.1", port), 3000)`。
- **后果**：每次 TCP 握手，使容器内 Node.js 的事件循环被从 `epoll_wait` 唤醒执行 `accept4`，产生极为规律的 15 秒脉冲。

### 4. 每 100 毫秒技能目录暴力轮询：`dsh-skill-filesystem` 退化
- **代码位置**：`@deepseek-ai/dsh-skill-filesystem/lib/index.js`
- **底层铁证**：`strace` 抓到大量高频密集调用：
  ```text
  statx(..., "/root/.agents/skills", ...) = -1 ENOENT (No such file or directory)
  statx(..., "/root/.dsh/skills", ...) = -1 ENOENT (No such file or directory)
  statx(..., "工作区/.agents/skills", ...) = -1 ENOENT
  ```
- **机制**：上游 Chokidar 监听技能目录时，因上述目录不存在，自动退化为 Node 原生 `watchFile(..., { interval: 100 })` 轮询模式，每秒调用 10 次 `statx` 扫描磁盘。

### 5. 每 300 毫秒停止任务轮询：`dsh-task-notifier`
- **代码位置**：`app/src/main/assets/task-notifier/lib/index.js`
- **机制**：内置插件每 300ms 通过 `setInterval` 检查 `.cancel_requested` 和 `.pending_prompt` 文件。

### 6. 待机睡眠彻底阻断元凶：永久占有的 `WakeLock` 与 `WifiLock`
- **代码位置**：`app/src/main/java/com/deepseekharness/app/HarnessService.java`
- **机制**：服务启动无条件调用 `wakeLock.acquire()`（`PARTIAL_WAKE_LOCK`）与 `wifiLock.acquire()`，无超时时间且无熄屏释放逻辑。
- **后果**：Android Linux 内核被强行剥夺进入 **Suspend（深度睡眠 / Deep Sleep）**的能力。CPU 时钟无法停振，上述各项定时器得以在锁屏后继续全速轰炸 CPU，造成夜间发热掉电。

## 三、 深度优化与根治方案实施

针对上述六大心跳与功耗源，实施了系统级的重构与加固：

### 1. 抽屉生命周期加固与 Token 智能对齐（`QuickChatSheetActivity.java`）
- **后台冻结**：在 `onPause()` 中调用 `sCachedWebView.onPause()` 与 `sCachedWebView.pauseTimers()`，抽屉收起或切到后台时瞬间定格 V8 引擎与渲染管线，每秒 CPU 空转立即归零；
- **唤醒解冻与代次识别**：在 `onResume()` 中调用 `resumeTimers()`，并比对服务代次 `controller.getWebGeneration()`：
  - 若代次未变：保持 0 毫秒秒开，不重新联网加载；
  - 若代次变化（服务重启过）：自动拉取最新 `launchtoken` 重新加载，彻底杜绝 401 报错；
- **附件上传 Cookie 同步**：在重载前通过后台线程调用 `controller.exchangeDshAuthCookie()` 并注入 `CookieManager`，保证 Web Worker 二进制附件上传始终有效；
- **右上角「+」号双层路由升级**：
  - 常态下 100% 走 DOM 快速探测（`btn.click()`），毫秒级创建新会话；
  - 若检测到底层服务重启或脱离地址，自动携带最新 Token 重新载入主页，保证新会话可用。

### 2. 动态 WebSocket 心跳策略（`HarnessController.java` & `LanProxyService.java`）
- **纯本机模式（默认）**：
  在启动前动态生成 `heartbeat-patch.yml` 补丁，将 `websocketHeartbeatIntervalMs` 设为 `2147483647`（约 24.8 天，等同彻底关闭心跳）；
  - **效果**：那每秒 `↑ 164 B/s ↓ 164 B/s` 的 2 秒 Ping/Pong 脉冲彻底归零！
- **局域网模式**：
  心跳间隔自动设为 `120000`（120 秒），既防止家用 Wi-Fi 路由器 NAT 断连，又将发包频率降低 98.3%；
- **启动参数顺序矫正（关键提交 4014c3a）**：
  严格将 `--patch` 放置在 `--no-open` 之前：
  `exec dsh web --patch /root/.dsh/heartbeat-patch.yml --no-open --host 127.0.0.1 --port 3080`，彻底消除 Commander 参数解析器抛出 `error: unknown option '--patch'` 导致的 Web 进程秒退。

### 3. 看门狗温柔化（`HarnessService.java`）
- 将探活周期 `KEEPALIVE_INTERVAL_MS` 从 `15000L` 大幅放宽至 **`60000L`（60 秒）**；
- 巡逻敲醒 Node 的频率降低 75%，大幅减轻系统唤醒负担。

### 4. 息屏联动与智能放锁机制（Dynamic WakeLock，恢复 Deep Sleep）
- 在 `HarnessService.java` 注册屏幕广播 `ACTION_SCREEN_OFF`、`ACTION_SCREEN_ON`、`ACTION_USER_PRESENT`；
- **用户锁屏睡觉（`SCREEN_OFF`）**：
  检查当前是否有活跃 AI 任务（`HttpShellService.isTaskActive`）：
  - **无任务在跑**：**立即主动释放 `wakeLock` 与 `wifiLock`！**
  - 看门狗 `dsha-keepalive` 在熄屏无任务时**自动跳过向 3080 端口发起的 TCP 探活连接**；
  - **效果**：解除系统层面的唤醒钳制，**手机系统顺利滑入 Linux 内核的 Deep Sleep（深度睡眠）**，CPU 时钟彻底停振；
- **用户亮屏使用（`SCREEN_ON`）**：重新获取锁，确保前台响应极速；
- **长任务协同**：长任务运行期间维持锁，任务结束（发送通知栏或用户点停止）联动放锁进入深度睡眠。

### 5. 补齐技能空目录与消除 100ms 轮询
- 在 `HarnessController.java` 启动流程中，自动在容器与工作区补齐 4 个空目录：
  `/root/.agents/skills`、`/root/.dsh/skills`、`工作区/.agents/skills`、`工作区/.dsh/skills`；
- 同时在补丁中注入 `watchPollIntervalMs: 60000`；
- **效果**：Chokidar 不再退化为 100ms 暴力扫描，挂入 Linux 内核原生 inotify 事件休眠。

### 6. 任务停止响应降频
- 将 `task-notifier` 监听通知栏停止与文字输入的 `setInterval` 从 `300ms` 调整为 **`1500ms`**，对文件系统的探查频率降低 80%。
