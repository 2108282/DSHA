# 容器启动死锁、软重启闪退与开机自愈排查记录 (容器启动死锁与软重启排查记录.md)

本文档记录了针对“测试过程中偶尔发生软重启、软重启后容器无法启动反复闪退、非要长按电源键硬重启才能恢复”的深层排查经过、底层机理剖析与极简生产级修补方案。

---

## 一、 核心现象复盘

1. **现象 1（软重启）**：
   在进行应用前后台高频切换、或多任务卡片滑动时，偶尔发生系统界面黑屏并触发用户空间软重启（Soft Reboot）；
2. **现象 2（开机循环死锁）**：
   软重启后系统经常卡在开机动画进不去系统，必须长按电源键强制硬重启（冷开机）才能进桌面；
3. **现象 3（容器启动反复闪退）**：
   在某些异常恢复或移动蜂窝网络（未连 Wi-Fi）环境下，打开 DSHA 启动容器时秒退或 15 秒超时闪退。

---

## 二、 底层三大根因剖析（转储与抓包实测证据）

### 1. 软重启引爆点：HyperOS 3.0 SurfaceFlinger 多任务缩略图抓取 Bug
* **崩溃进程**：`/system/bin/surfaceflinger`（`tombstone_15`，时间戳 `19:41:04`）
* **崩溃堆栈**：
  ```text
  Abort message: 'bad_variant_access was thrown in -fno-exceptions mode'
  #04 android::SurfaceFlinger::renderScreenImpl(...)
  #03 android::Layer::prepareReleaseCallbacks(...)
  #02 std::__1::__throw_bad_variant_access()
  ```
* **机理**：小米桌面（`com.miui.home`）在多任务滑动时高频调用 `screenshotTaskForU` 抓取后台缩略图过渡动画。小米魔改的 `libsurfaceflinger.so` 在处理释放中的混合图层时抛出 `std::variant` 越界异常，导致系统图形中枢直接 abort 退出，引爆软重启。

### 2. 卡开机死锁点：Android 16 `netd` 守护进程在软重启下的 eBPF 冲突
* **崩溃进程**：`/system/bin/netd`（连续生成 `tombstone_16` ~ `tombstone_31`，连续崩溃 16 次！）
* **崩溃堆栈**：
  ```text
  #01 /apex/com.android.tethering/lib64/libnetd_updatable.so (libnetd_updatable_init)
  #02 /system/bin/netd (main)
  ```
* **机理**：`init.rc` 规定 `netd` 重启必须同时重启 `Zygote`。由于软重启时 Linux 内核并未重启，内核里的 `/sys/fs/bpf` 网络规则处于被占用状态。`netd` 重建失败直接触发崩溃循环，导致手机卡在开机画面。**只有长按电源键彻底硬件断电冷启动，内核完全重载，`netd` 才能正常初始化**。

### 3. 容器启动死锁点：清场逻辑“免死金牌”导致孤儿 proroot 残留
* **排查证据（`dsha-activity.log`）**：
  ```text
  Web 启动超时，但容器能正常执行命令（15 秒未就绪）
  10252 ppid=5147 | libproroot.so    <-- 上次崩溃残留的孤儿 proot！
  11563 ppid=5147 | libproroot.so    <-- 另一个孤儿 proot！
  ```
* **代码逻辑硬伤**：
  原版 `WebProcSel.looksLikeWeb()` 中为了防止误杀当前容器，写死了硬编码规则：
  `if (cmd.contains("libproroot") || cmd.contains("libproot")) return false;`
  导致宿主 App 上次崩溃后留下的孤儿 `libproroot.so` 永远杀不掉。新容器拉起时一头撞上旧孤儿，发生虚拟文件系统挂载冲突死锁，导致新容器启动超时闪退。
* **次要隐患（蜂窝网络空指针）**：
  在无 Wi-Fi 或蜂窝运营商分配非内网段 IP 时，`HarnessController.getLanAddress()` 返回 `null`，引发 `LanProxyService.java:120` 的 `lanIp.isEmpty()` 偶发报 NPE 闪退。

## 三、 极简生产级修补方案（不推倒、不重构，精准打补丁）

### 1. `LanProxyService.java`（防空指针秒退）
```java
// 保证 lanIp 永远不为 null
String ip = HarnessController.getLanAddress();
lanIp = ip != null ? ip.trim() : "";
```

### 2. `HarnessController.java`（清场时精准收割孤儿 proroot）
在 Android 宿主清场遍历 `/proc` 时，基于同 UID 权限和 PPID（父进程 ID）进行精准识别：
```java
boolean isTarget = WebProcSel.looksLikeWeb(cmd);
// 关键防死锁修补：对于包含 libproroot/libproot 的进程，如果它绑定的 rootfs 正是本 App 的目录，
// 且它的父进程已经不是当前正在运行的 App 实例（即 ppid != self），说明是上次崩溃或软重启残留的死体孤儿，必须清理！
if (!isTarget && (cmd.contains("libproroot") || cmd.contains("libproot.so"))) {
    String myRootfs = getRootfsDirPath();
    if (myRootfs != null && cmd.contains(myRootfs)) {
        int ppid = readProcPpid(pid);
        if (ppid != self) {
            isTarget = true;
            android.util.Log.w("DSHA", "识别到残留孤儿 proot 进程 pid=" + pid + ", ppid=" + ppid);
        }
    }
}
if (!isTarget) continue;
// 原版 android.os.Process.killProcess(pid) 正常收割
```

### 3. `ContainerRuntime.java`（挂载前清理私有共享内存残留）
在绑定挂载私有 `cache/shm` 目录前，清理历史残留的 POSIX 共享内存段文件，杜绝段损坏带来的 Node.js 启动总线错误。

## 四、 零误杀与安全性论证

1. **物理跨域隔离**：普通应用执行 `killProcess(pid)` 受 Linux 内核 UID 强制约束，绝对无权碰系统或其它 App 任何进程；
2. **正常运行免检**：只要旧容器健康答复 HTTP，启动首行 `WebProbe.servesHttp` 直接接管退出，根本不进清场逻辑；
3. **自身子进程免伤**：当前进程派生的子容器满足 `ppid == self`，受严格保护；
4. **路径精准对齐**：仅当命令行包含 DSHA 自己的 `rootfs` 路径且 `ppid != self` 时才命中，100% 毫无误杀可能。
